# conda-maintainers Team Planning

This repo is for managing planning for the conda-maintainers team in order to capture issues and documentation across repositories that we work on.

## conda-maintainers

Maintainers of conda and related core plugins

This is a temporary home for information about the team, this should be hosted at https://conda.org once
https://github.com/conda/conda-dot-org/pull/285 is merged.

## Requirements

This team is defined as a community project team.

New members may join through the Conda Governance [nomination process](https://github.com/conda/governance?tab=readme-ov-file#nominate-new-member-of-a-community-project-team).

## Emeritus Members

Members that are inactive (commits, GitHub comments/issues/reviews, dev meetings, and voting on polls) in the past six months will be asked if they want to become Emeritus members. One week after asking, if the inactive member has not responded, they will be automatically moved to emeritus status. Any member can also request to become Emeritus if they wish to do so (e.g. taking a sabbatical or long vacation). Members can be brought back to active membership at anytime. Emeritus members no longer have maintainer access on repositories.

## Special Roles

**Technical Lead** - Leads major architectural decisions (solver behavior, plugin APIs, deprecation schedules, cross-platform behavior). Escalation facilitator when lower level disputes can't reach rough consensus at the PR level. Must agree on feature-level technical requirements and designs before they are finalized.
- @jezdez

**Planning Lead** - Helps define the roadmap, PI objectives, and release sequencing across conda/conda-maintainers projects. Assigns and rotates Feature Owners from the members for major initiatives.
- @danyeaw
